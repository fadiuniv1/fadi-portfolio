Notes

Short lessons from building in public. These started as posts on X and LinkedIn.

4 things I learned reading other people's open source

Local-first is a feature: tools that run offline earn trust immediately. Checkpoints beat full autonomy: the best agent projects stop and ask a human before consequential steps. Docs are part of the code: one copy-paste command did more for adoption than any clever implementation. Small and boring wins: a one-file tool with a test is easier to learn from than a 50-module framework.

Original thread
Most "context window errors" are "I pasted node_modules"

The fix is not a bigger window. Rank files by usefulness, respect .gitignore, redact secrets, and omit the boring stuff instead of truncating at random. That became contextpack: a local CLI that fits a real prompt into a real budget, with headroom left for the answer.

Read the tool
Stop filling the context window to the last token

A prompt that consumes the entire window leaves the model nowhere to answer. I changed contextpack to reserve 12% for the question and response, cap any single file at 25% of the usable budget, and show a structural outline instead of dropping oversized files. The result is a usable prompt, not a full window of raw text.

contextpack v0.2.0
GitHub badges are not a hiring signal

YOLO means you merged a PR without review. Quickdraw means you closed an issue within five minutes. Funny badges, but not the signal I want to send. The lesson: speed is easy, judgement isn't. Every PR gets a reader, every tool gets a test, every issue stays open 24 hours before I close it.

Original post
Three Linux habits that saved more time than any tutorial

Read the man page before searching. Run git status before every commit. Keep a scratch file of commands you always forget and lose. The third one is the one that compounds — and it is basically session memory for your future self.

Automation work
What --diff is actually for

Packing only the files you changed turns a 30,000-token code-review prompt into a few hundred. contextpack includes modified, staged and untracked text files relative to a git ref, so the model reviews your work instead of your dependencies.
